# 番茄后台踩坑记录

这份文档记录实际跑完一本 175 章小说过程中踩到的所有坑。遇到异常先查这里，能省掉几小时。

---

## 一、报错对照表

| 现象 | 真实原因 | 解法 |
|---|---|---|
| `code:-3011 本书中存在重复标题，请修改后再发布` | 书名级去重：**全书任意两章标题相同就拒**。原稿本身可能就有重名 | 改其中一章的标题，写进 `titleFix` |
| 编辑器红字「标题至少输入5个字」 | 番茄按"连续数字算 1 个字"计数。`第56章 哥` = 4 字 | 标题补长到 ≥5 字 |
| 点了「确认提交」没反应，页面停在编辑器 | 90% 是上面两种错误之一，错误以 toast 形式出现 3 秒就消失，脚本容易漏看 | 抓 `.arco-message` / `.arco-notification` 的文本 |
| 上传后草稿数没增加 | 解析完只进了预览，没点「保存」；或弹了「确定保存吗」没点「继续保存」 | 两个按钮都要点 |
| 草稿箱里出现重复章节 | 提交失败后草稿残留，再次上传又建了一份 | `clear_drafts.js --go` 清空重来 |
| 提交时打开的是别的章内容 | 草稿 id 与章号映射错位（草稿箱有残留时极易发生） | 清空草稿箱后重新上传，提交前先核对 `input.serial-input` 的值 |
| 本地记录"已发"但线上没有 | 脚本把"页面无报错"当成成功 | 用 `verify.js` 以线上数据为准 |

## 二、界面交互的坑

### 1. 草稿箱必须用 type=2 直接访问

```
正确：/main/writer/chapter-manage/{bookId}&{书名}?type=2
错误：先 goto type=1 再 getByText('草稿箱').click()
```

点 tab 切换后表格经常仍显示「章节管理」的数据，抓出来的章号全是已发布章节。这是排查最久的一个坑——表现为"草稿箱明明只有 6 篇，却抓到 30 个章号"。

### 2. 新手引导浮层的「下一步」和顶部按钮重名

进编辑页首次会弹 3 步引导，其中的按钮也叫「下一步」。用文本定位必然点错。

按坐标区分：

```js
const box = await btn.boundingBox();
if (box.y > 100) { /* 浮层里的，点它 */ }
if (box.y < 100 && box.x > 800) { /* 顶部的，后面再点 */ }
```

### 3. 引导走完还有一道合规提示

浮层关掉后弹「注意平台不允许发布以下内容…」，必须点「我知道了」才能点顶部「下一步」。不处理就会被 `arco-modal-wrapper` 拦截点击，报 `subtree intercepts pointer events`。

### 4. 编辑器是三块独立输入

| 元素 | 选择器 |
|---|---|
| 章节号 | `input.serial-input`（第一个） |
| 标题 | `input[placeholder="请输入标题"]` |
| 正文 | `div.ProseMirror`（第一个） |

**章节号单独填数字，标题只填标题本身，不要把「第106章」写进标题框**，否则会变成「第106章 第106章 夏远」。

### 5. 提交弹窗是连续三个，且不一定全出现

```
顶部「下一步」
  → 「发布提示：还有错别字未修改」→ 提交        （不一定出现）
  → 「请选择内容检测方式」→ 仅基础检测          （不一定出现）
  → 「发布设置」→ 是否使用AI 选否 → 确认提交
```

每个都要写成"有就点、没有就跳过"，不能硬等。

### 6. 新手引导只弹一次

同一浏览器 profile 下，第 2 章开始不再弹引导。但换 profile 或清 cookie 后会重新弹。脚本要能容忍两种状态。

## 三、发布策略

### 章节顺序按发布时间，不按章节号

后台列表和阅读端目录都按**创建/发布先后**排。补发的第 106 章会出现在第 175 章后面。

- 网页后台**没有任何排序功能**，「设置」里只有标点和纠错选项
- 「编辑分卷」只能新建分卷，不能拖动章节
- 唯一补救：番茄作家助手 APP → 我的 → 帮助与反馈 → 章节编辑 → 「发错章节顺序怎么办」，**发布后 3 天内有效**

**结论：批量发布必须一次按 1→N 顺序做完。** 分批发或中途补发，顺序必乱。

### 每日发布上限

番茄有每日发布上限，但具体数字未公开。实测单日连续发 175 章没有被拦截，但脚本仍建议每批 30 章核对一次，避免一次性跑飞。

### 内容检测次数

「全面检测」每章有剩余次数（如 2/2），「仅基础检测」不限次数。批量发布选基础检测，否则次数很快耗尽。

## 四、合规

### 「是否使用AI」是作者声明项

番茄发布设置里有这个必选项，不选发不出去。**必须如实填写**——虚假声明的处罚是下架 + 封号，比标注 AI 的代价大得多。

脚本通过 `config.json` 的 `useAI` 控制，默认 `false`。这个值应由作者本人确认，不要代填。

### 独家授权

番茄签约默认要求独家信息网络传播权。如果同一部作品已在其他平台（七猫、起点等）**正式发布**（投稿未过审不算），番茄这边会被判非独家，影响签约。上架前先确认。

### 内容审核

末世/悬疑题材注意：未成年人受害细节、过度血腥、秩序失控描写容易被人工复审。上架前建议自查。

## 五、环境

### 无头模式的坑

`chromium.launch({ headless: true })` 会去找 `chrome-headless-shell`，Playwright 新版默认不下载，报 `Executable doesn't exist`。

用完整 Chromium 加参数实现无头：

```js
chromium.launch({ headless: false, args: ['--headless=new'] })
```

这样窗口不弹，但走的是完整浏览器内核，反检测特征也更好。

### 反自动化

```js
args: ['--disable-blink-features=AutomationControlled']
// 并在 context 里注入
Object.defineProperty(navigator, 'webdriver', { get: () => undefined });
```

另外每章之间随机等待 6-14 秒，不要连续高速请求。

## 六、脚本设计上的教训

1. **不要用"页面无报错"判断成功。** 改成：先核对 `input.serial-input` 的值是否等于目标章号，再抓 toast 里是否含「成功」或 URL 是否离开编辑页。
2. **本地进度文件不可信。** 每次批量操作后必须用 `verify.js` 以线上数据核对。
3. **草稿箱的 id 映射在草稿有残留时会错位。** 提交前必须验证，否则会把 A 章的内容当成 B 章发出去。
4. **先清空草稿箱再上传**，能规避上面大半问题。
